# 开发规范规则

## 概述
本文档定义了项目开发过程中必须遵循的文档更新规范，确保技术文档、进度记录和组件说明始终保持最新状态。

## 文档更新规则

### 1. 组件相关开发
**触发条件**：开发和打包微信小程序组件相关的任务

**必须更新的文档**：
- `e:\Project\fsj\merchantDashboard\components\README.md`

**更新内容要求**：
- 新增组件时：添加组件说明文档，包括作用、功能特性、可配置属性、使用场景
- 修改组件时：更新对应组件的功能说明和属性配置
- 删除组件时：移除对应的组件说明
- 更新组件开发规范部分（如果有变化）
- 更新数据绑定和排序规则说明（如果有变化）

**示例场景**：
- 新增一个视频组件 → 在 README.md 中添加视频组件的完整说明
- 修改轮播图组件的属性 → 更新轮播图组件的可配置属性列表
- 调整组件的数据绑定逻辑 → 更新数据绑定部分的说明

---

### 2. 技术路线相关开发
**触发条件**：任务中提到和技术路线相关的内容

**必须更新的文档**：

**更新内容要求**：

- 修改技术方案：更新相关的技术实现细节
- 补充技术细节：完善技术路线中缺失的实现说明
- 更新架构图或流程图（如果有变化）

**示例场景**：
- 实现算法推荐功能 → 在技术路线的「算法推荐模式」部分补充实现细节

### 3. 需求补充和功能开发
**触发条件**：根据需求有需要补充的内容

**必须更新的文档**：
- `e:\Project\fsj\开发进度.md`

**更新内容要求**：
- 新功能开发：在「待开发功能」章节添加对应的待办项
- 功能完成：将待办项从「待开发功能」移动到「已完成功能」
- 功能改进：在「改进记录」章节添加改进说明
- Bug修复：在「改进记录」章节记录问题和解决方案
- 进度更新：按照最小单元拆分任务，确保每个任务可独立验证

**更新格式要求**：

**新增待办项格式**：
```markdown
### X. 模块名称
- [ ] 具体任务描述
- [ ] 具体任务描述
```

**完成任务格式**：
```markdown
### X. 模块名称
- [x] 具体任务描述
```

**改进记录格式**：
```markdown
- 日期：YYYY-MM-DD
- 模块：模块名称
- 关联条目：勾选项（如：### 1. 算法推荐能力接入）
- 问题描述：具体问题描述
- 改进方案与效果：改进措施和效果说明
```

**示例场景**：
- 开始开发算法推荐 → 在「待开发功能」中添加「算法推荐能力接入」模块
- 完成数据绑定UI → 将对应待办项标记为 `[x]` 并移到「已完成功能」
- 修复底部导航栏样式问题 → 在「改进记录」中添加记录

## 版本号管理规则

### 触发条件
每次修改小程序打包代码时

### 必须更新的内容
- `e:\Project\fsj\merchantDashboard\server.js` 中的版本号常量

### 版本号格式
```javascript
const MINIPROGRAM_VERSION = '1.0.2';
```

### 版本号规则
- **主版本.次版本.修订号**（如：1.0.2）
- **重大更新**：增加主版本（1.0.2 → 2.0.0）
- **新功能**：增加次版本（1.0.2 → 1.1.0）
- **Bug修复**：增加修订号（1.0.2 → 1.0.3）

### 版本号打印位置
1. **小程序启动时**（app.js）
   ```javascript
   console.log('小程序启动');
   console.log('小程序版本: 1.0.2');
   ```

2. **页面加载时**（index.js）
   ```javascript
   console.log('首页页面加载');
   console.log('小程序版本: 1.0.2');
   ```

### 更新流程
1. 修改 `server.js` 中的 `MINIPROGRAM_VERSION` 常量
2. **[手动操作]** 提交代码到 Git（使用 GitHub Desktop 或命令行：`git add .`, `git commit`, `git push`）
3. **[手动操作]** 在服务器上拉取最新代码（SSH 连接到服务器，执行 `git pull`）
4. **[手动操作]** 重启 PM2 服务（SSH 连接到服务器，执行 `pm2 restart miniprogram-generator-3001`）
5. **[手动操作]** 重新打包小程序（打开宝塔装修页面，点击"打包小程序"按钮）
6. **[手动操作]** 在微信开发者工具中导入并查看控制台，确认版本号已更新
7. **[手动操作]** 测试功能是否正常

**重要说明**：
- 本地代码通过 Git 同步到宝塔服务器（`/www/wwwroot/100000whys.cn/project/fsj/merchantDashboard`）
- 修改代码后必须重启 PM2 服务才能生效
- PM2 重启命令：`pm2 restart miniprogram-generator-3001`
- 如果不重启 PM2，服务器仍运行旧版本代码，导致修改不生效

### 示例场景
- 修复轮播图数据加载问题 → 版本号从 1.0.1 更新到 1.0.2
- 新增版本号打印功能 → 版本号从 1.0.0 更新到 1.0.1
- 重构数据加载架构 → 版本号从 1.0.2 更新到 2.0.0

## 注意事项

1. **及时更新**：文档更新应与代码开发同步进行，不要延迟到任务结束
2. **准确性**：确保文档内容与实际代码实现完全一致
3. **完整性**：不要遗漏任何需要更新的文档内容
4. **规范性**：严格按照文档格式要求进行更新
5. **可追溯性**：改进记录应包含足够的细节，便于后续追踪
6. **最小单元**：任务拆分应遵循最小单元原则，确保每个任务可独立验证
7. **版本管理**：每次修改代码必须更新版本号，便于追踪问题
8. **手动操作标记**：待办任务中如果包含需要手动操作的内容（如重启 PM2、重新打包小程序等），应在任务描述中明确标注，避免遗漏
9. **重启提示**：只要任务涉及需要重启服务，必须在对话结束时提示执行相关重启命令
10. **明道云键值命名规范**：进行明道云数据结构规划时，键值名称采用拼音全拼，不用英文单词。中文为三个字的全拼，超过三个字采用首字母缩写，不使用驼峰命名。例如：标题→mingcheng，描述→miaoshu，封面→fengmian，标签→biaoqian，价格→jiage，作者头像→zztx，作者昵称→zznc。**注意**：创建时间使用系统字段 ctime，不需要使用拼音

## 服务器端口与路径对应关系

| 端口 | 进程名称 | 路径 | 功能 |
|------|---------|------|------|
| 3001 | server.js | `/www/wwwroot/100000whys.cn/project/fsj/merchantDashboard` | 小程序打包生成 |
| 3003 | wxApp.js（经 start-3003.js 启动） | `/www/wwwroot/100000whys.cn/project/fsj/merchantDashboard` | 打包小程序与登录相关 API（wx.login、手机号一键登录等） |

**说明**：3003 与 3001 同目录，运行 `start-3003.js`，内部加载 `wxApp.js` 并监听 3003 端口，承载打包后小程序调用的所有登录相关接口。

### PM2 重启命令
```bash
# 3001 打包服务
pm2 restart miniprogram-generator-3001

# 3003 打包与登录 API（进程名以 pm2 list 为准，如 api-3003）
pm2 restart api-3003

# 或者重启所有
pm2 restart all
```
