## 三、改进记录

> 用于记录已上线功能的优化与修正历史，便于后续追踪。

- 日期：2026-02-20
- 模块：数据加载架构
- 关联条目：### 2. 组件系统与页面代码生成
- 问题描述：之前采用服务器端加载数据的方案，打包时调用明道云 API 获取数据并写入小程序代码。但多次尝试后发现服务器端数据加载失败，轮播图数据一直为空，且每次打包都需要重新加载数据，效率低下。
- 改进方案与效果：改为小程序端自行加载数据的架构。在生成的小程序页面代码中添加数据加载方法（load轮播图Data、call轮播图API），小程序启动时直接调用明道云 API 获取数据。优势包括：数据实时更新、无需重新打包、逻辑更清晰、避免服务器端依赖问题。同时去掉了过滤条件，解决了数据为空的问题。

- 日期：2026-02-20
- 模块：版本号管理
- 关联条目：### 2. 组件系统与页面代码生成
- 问题描述：之前没有版本号管理机制，无法追踪小程序代码版本，出现问题时不清楚是哪个版本的代码，难以定位和修复问题。
- 改进方案与效果：在 server.js 中添加 MINIPROGRAM_VERSION 常量，在小程序启动和页面加载时打印版本号。每次修改代码必须更新版本号，便于追踪问题和验证更新是否生效。在 project_rules.md 中添加版本号管理规则，规范版本号格式和更新流程。

- 模块：组件 WXML 数据绑定
- 关联条目：### 2. 组件系统与页面代码生成
- 问题描述：轮播图和功能列表组件的 WXML 生成逻辑使用了硬编码的静态内容（component.componentItems.map），而不是使用小程序的数据绑定（wx:for）。这导致即使小程序端成功加载了数据，也无法在界面上显示，因为 WXML 没有绑定到数据源。

- 关联条目：### 1. 门店装修基础框架
- 问题描述：所有页面的组件库显示相同的组件列表，没有根据页面类型进行区分，导致用户在"我的"页面也能看到首页相关的组件（如轮播图、功能列表等），造成组件选择混乱
- 改进方案与效果：实现了页面级组件筛选机制。"我的"页面被识别为特殊页面，当在页面树中选中"我的"页面时，组件库中只显示与"我的"页面相关的特殊组件（我的订单、会员权益消耗明细、登录用户协议、新手引导、设置等）。实现原理是为每个组件添加 relatedPage 属性，标识该组件属于哪个页面。当选中"我的"页面时，只显示 relatedPage === 'my' 的组件；其他页面（首页、分类等）显示 relatedPage === 'home' 或 relatedPage === 'category' 的组件。这样确保不同页面的组件不会混淆，提升用户体验。
