# 颜色同步问题排查清单

## 目标
定位“全局设置里颜色能改，但预览或文本/导航栏不变”的根因。

## 排查顺序
按从“最快验证”到“影响面最大”的顺序执行。

## 1. 事件是否触发
- 在颜色输入控件 `oninput/onchange` 里临时打印当前值和对应 key
- 观察控制台是否连续输出
- 预期：拖动时能持续输出，松手时也能输出

## 2. 数据是否被正确写入
- 观察 `globalConfig` 和 `tabBarConfig` 的最新值
- 预期：对应字段应立即改变

## 3. 绑定元素是否正确
- 检查更新函数里定位到的元素是否存在
- 重点关注：
  - 预览色块元素
  - 文本输入框
  - 顶部导航栏容器
  - 底部 tabBar 容器
- 预期：这些元素应都能被定位到

## 4. 样式是否真正影响预览
- 检查实际展示区域的颜色来源
- 重点关注：
  - 顶部导航栏背景色是否被 CSS 写死
  - 顶部导航栏文字色/返回箭头是否被 SVG 写死
  - 底部导航栏选中/未选中色是否被 CSS 写死
- 预期：展示颜色应来自配置或动态样式

## 5. 是否被后续渲染覆盖
- 检查是否有 render 函数在颜色更新后重新写入默认值
- 重点关注：
  - renderPreview
  - renderTabBar
  - loadConfig 后的重绘
- 预期：重绘应使用最新配置

## 6. 是否存在多重样式冲突
- 检查是否同时使用了 CSS 变量和内联样式
- 检查是否存在更高优先级的样式覆盖
- 预期：动态设置的样式优先级最高

## 7. 浏览器原生色板行为差异
- 不同浏览器可能只在松手后触发 change
- 预期：若 oninput 不触发，至少 onchange 应触发
- 需要确认是否用的是同一个浏览器复现

## 8. 关联页面状态是否正确
- 确认当前左侧是“全局设置”视图
- 确认不是在 tabbar 视图或 page 视图中测试
- 预期：全局配置更新时，不应依赖选中的页面

## 9. 本地配置是否存在历史脏数据
- 清理 localStorage 的 `decorationConfig`
- 重新加载页面后再测试
- 预期：避免旧配置覆盖新变化

## 10. 最小复现实验
- 在最小 DOM 里放一个 color input + 一个 div
- 仅用 `oninput` 改 div 背景色
- 预期：若最小复现没问题，说明问题在页面结构或渲染链路
