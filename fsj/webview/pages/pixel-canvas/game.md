### 文件结构
#### 目录

#### 命名规范
页面目录名：使用小写字母和连字符（如 `pixel-canvas`）
页面文件：统一命名为 `index.html`、`index.css`、`index.js`
页面类：导出默认类，类名建议为 `PixelCanvasPage` 等语义化名称


### 禁用鼠标悬停样式
我们页面是在移动端，采用移动端友好操作样式，不需要悬停效果
其他PC逻辑才有的，对于移动端无效果的样式和交互都不需要

### 技术栈
JavaScript：ES6+（模块、类、箭头函数、async/await）
HTML5：Canvas API、语义化标签
CSS3：Flexbox、动画、rem 单位
浏览器兼容性：现代浏览器（支持 ES6 模块和 Canvas API）

### 三分离架构
HTML5+CSS+JS
DOM：每个页面独立的 `index.html` 文件
CSS：每个页面独立的 `index.css` 文件，通过 `<link>` 动态加载
JavaScript：每个页面独立的 `index.js` 文件，导出默认类作为页面组件
页面组件需实现 `destroy()` 方法用于资源清理

### 像素画渲染
保持像素画清晰度，避免模糊
禁用 Canvas 抗锯齿：`ctx.imageSmoothingEnabled = false`
禁用 CSS 抗锯齿：`image-rendering: pixelated; image-rendering: crisp-edges;`
使用整数倍缩放，避免非整数缩放导致的模糊
禁止使用 CSS `transform: scale()`，改用直接设置 `style.width/height`

### 交互性能
####点击角色
1.监听 Canvas `click` 事件
2.坐标转换：将屏幕坐标转换为 Canvas 逻辑坐标（系统级分辨率，120等分）
3.判断点击位置是否在角色边界框范围内（`charX <= x < charX + charWidth` 且 `charY <= y < charY + charHeight`），只要在边界框内就响应点击，不要求必须是像素位置
4.状态切换：`isSelected = !isSelected`
5.选中角色轮播描边：选中时显示角色轮廓描边，遍历角色像素数据（JSON格式），检查上下左右四个方向的邻居像素,如果邻居像素透明或超出边界，则绘制描边像素,描边沿角色实际轮廓绘制，非矩形框;颜色根据角色五行所对应的浅色；角色没有五行属性则默认为#00C5E8（蓝色）
6.点击角色聊天：点击角色AI立即发布一条信息到聊天框；底部居中，距离底部5px；背景#ffffff，边框0.03rem 颜色为全局样式最深黑色#030303；圆角0.1rem；宽度撑满，外边距左距右5px；滑入动画 `slideUp`，时长 `0.3s`，缓动函数 `ease-out`；初始状态：`display: none`，`aria-hidden="true"`，显示状态：添加 `show` 类，`aria-hidden="false"`

### 图片加载
步加载图片，避免阻塞渲染
使用 `Image` 对象异步加载
通过 `isImageLoaded` 标志位控制绘制时机
图片加载完成后调用 `redraw()` 重绘

### 资源清理
页面切换时清理资源，避免内存泄漏
页面组件实现 `destroy()` 方法
移除事件监听器：`window.removeEventListener('resize')`，`canvas.removeEventListener('click')`
清理图片引用：`this.characterImage = null`

### rem适配
基于 750px 设计稿的 rem 适配方案
基准：`html { font-size: 100px; }`（即 750px 对应 `7.5rem`，1rem = 100px）
所有尺寸使用 `rem` 单位
示例：`width: 6rem` = 600px（在 750px 设计稿中）
Canvas 自动缩放：根据屏幕宽度计算整数倍缩放

### 全局样式
最深色：#030303，描边、对话框描边、经验值字头、等级文字
次深色：#050505，对话框背景、等级文字背景
中色：#090909，按钮、进度条、等级文字背景

### HTTP服务器
必须通过 HTTP 服务器运行，不能直接打开 HTML 文件
ES6 模块（`type="module"`）需要 HTTP 协议
`fetch` API 在 `file://` 协议下会触发 CORS 错误
推荐：使用 Node.js `npx http-server -p 8080 -c-1`
备选：使用 Python `python -m http.server 8080`
访问地址：`http://localhost:8080/index.html`

### 错误处理
页面加载失败时提供友好的错误提示
HTML 加载失败：使用内联 HTML 作为降级方案
页面模块加载失败：显示错误信息，提示用户使用 HTTP 服务器运行
图片加载失败：在 Canvas 上显示错误文本

#### pixel canvas的游戏规则

##### 像素调色板（`webview/color.json`）与成像规则

- **调色板数据来源**
  - 所有像素颜色统一由 `webview/color.json` 提供，为一个 **11 行 × 10 列** 的二维数组，共 **110 个颜色**。
  - 每个颜色存储为 6 位十六进制字符串（不带 `#`），渲染到 Canvas 时再转换为 `#RRGGBB`。
  - **游戏内所有像素颜色必须来自这一调色板，不允许使用调色板之外的任意颜色值。**

- **成像数据结构**
  - 角色、场景等像素图的成像数据统一使用 **二维数组** 表示：
    - 数组元素类型为：`""` 或 `0 ~ 110` 的整数。
    - `""`（空字符串）表示**透明像素**（不绘制，保留底色）。
    - `0` 表示颜色 `#FFFFFF`，用于纯白背景。
    - `1` 表示颜色 `#FED7DC`（调色板中第一行的第一个红色）。
    - `10` 表示颜色 `#181818`（第一行灰度的最深色）。

- **颜色编号与色系对应关系**
  - **第 0 行（灰度）**：编号 `0 ~ 10`
    - `0`：`#FFFFFF`（纯白）——特殊保留，用于白底。
    - `1 ~ 9`：从浅灰到深灰。
    - `10`：`#181818`，灰度的最深色。
  - **第 1 行（红色系）**：编号以 **2 开头**
    - `2x` 表示红色系从浅到深的 10 个色阶。
    - `20` 约定为**红色描边色**，对应该行中最深的红色（用作角色/素材的红色轮廓线）。
  - **第 2 行（橙色系）**：编号以 **3 开头**
    - `3x` 表示橙色系从浅到深的 10 个色阶。
    - `40` 为橙色系的**描边色**，对应该行中最深的橙色。
  - 依此类推，按行定义色系（十位数 = 色系编号）：
    - `4x`：黄色系，`50` 为黄色描边色。
    - `5x`：嫩绿色系，`60` 为嫩绿描边色。
    - `6x`：绿色系，`70` 为绿色描边色。
    - `7x`：青色系，`80` 为青色描边色。
    - `8x`：蓝色系，`90` 为蓝色描边色。
    - `9x`：靛色系。
    - `10x`：紫色系。

- **描边色（轮廓线）约定**
  - **所有素材外圈统一使用 `#181818` 颜色描边**。
  - 规则：无论素材使用哪个色系，外轮廓线都必须使用 `#181818`（对应颜色编号 `10`，灰度最深色）。
  - 渲染角色/素材时：
    - 填充色使用对应色系的编号（例如 21, 22, 23…）。
    - 轮廓线统一使用 `#181818` 描边，确保所有素材风格统一。

- **提示词驱动素材生成约定**
  - 用户通过提示词创建角色/素材时，只需要指定：
    - 使用哪一行的色系（例如“红色系”“蓝色系”“土元素色系”等）。
    - 以及大致的明暗层级（例如“浅色”“深色”“描边色”）。
  - 系统将提示词转换为具体的 **颜色编号数组（0~110 + ""）**，再映射到 `webview/color.json` 中的实际颜色。
  - 这样可以保证：
    - 所有生成的角色和素材严格使用统一调色板，风格一致。
    - 后续可以安全替换整个调色板，而不需要修改任何像素素材数据结构。

### AI信息
1. 名称
2. 等级
3. 经验值
4. 互动值
5. 魅力值（仅限分身）
6. 能量点（token）

### AI类型
分身：用户的真人分身
AI：用户创建的AI
系统助理：每个用户自创建账号起，系统创建的AI助理；用户可以其升级为AI助理

### AI包含的功能
1. 商城：当前AI能提供的产品和服务
2. 充电：当能量点不足时，呈现休克状态，用户可以在充电购买能量点，访客也可以为他充电
3. 卡牌：大脑卡牌（智谱、Deepseek、OpenAI等）、技能卡牌、性格卡牌、知识卡牌、任务卡牌
4. 拍拍：一种互动方式，访客可以通过拍拍动作AI增加互动值
5. 送花：访客可以通过送花增加互动值，收到花的用户会增加魅力值
6. 任务：包含系统任务、卡牌任务，通过卡牌组合会生成其他任务，任务会自动分配到任务系统
7. 想法：AI通过想法可以把卡牌任务分解出子任务，也可以发展其他任务
8. 消息：点击消息跳转到聊天页面
9. 系统任务：手机绑定、个人信息填写、剧情任务等

### 界面色设计及UI
UI分两种分辨率

#### 系统级分辨率=屏幕宽/120
**说明**：系统级分辨率用于功能图标、信息框等UI元素。计算公式：`系统级分辨率单位 = 屏幕宽度 / 120`（单位：px）

**示例**：在750px宽度的屏幕上，1个系统级分辨率单位 = 750/120 = 6.25px

**功能图标尺寸规则**：
- **功能图标图片原始尺寸**：16px × 16px（图片文件的实际像素尺寸）
- **功能图标显示尺寸计算公式**：`图标显示尺寸 = (屏幕宽度 / 120) × 16`
  - 在750px屏幕上：图标显示尺寸 = (750/120) × 16 = 6.25 × 16 = 100px
  - 在390px屏幕上：图标显示尺寸 = (390/120) × 16 = 3.25 × 16 = 52px
- **功能图标间距**：2个系统级分辨率单位 = `2 × (屏幕宽度 / 120)`
- **实现方式**：在JavaScript中计算 `(window.innerWidth / 120) * 16`，设置为CSS变量 `--function-icon-size`，CSS中使用 `width: var(--function-icon-size); height: var(--function-icon-size);`

  - 第1段：较浅色 `#00C5E8`
  - 第2段：浅色 `#00A2E8`
  - 第3段：深色 `#0087E8`
  - 第4段：较深色 `#0064E8`
- **层级**：cengji=3（z-index: 3，在信息框之上）
- **实现方式**：
  - 在JavaScript中计算 `(window.innerWidth / 120) * 72` 和 `(window.innerWidth / 120) * 2`，设置为CSS变量 `--exp-bar-width` 和 `--exp-bar-height`
  - HTML结构：`expBarGrid` 容器内包含4个 `exp-bar-segment` 子元素
  - CSS使用 `display: flex` 横向排列，每段宽度为 `calc(var(--exp-bar-width) / 4)`
- **元素ID**：`expBarGrid`（后续可用于动态更新经验值进度）

#### 统一分辨率系统（屏幕宽/120）
**说明**：所有素材（包括角色、UI元素等）统一使用**系统级分辨率**（屏幕宽度 / 120）。不再区分角色场景级分辨率和系统级分辨率。

**计算公式**：`系统级分辨率单位 = 屏幕宽度 / 120`（单位：px）

**示例**：在750px宽度的屏幕上，1个系统级分辨率单位 = 750/120 = 6.25px

**角色渲染规则**：
- 角色数据（JSON格式）宽度为 **120等分**（系统级分辨率）
- Canvas逻辑宽度固定为 **120px**（系统级分辨率单位）
- 角色数据与Canvas为 **1:1映射**，无需缩放
- 角色在Canvas中居中显示

**角色数据格式**：
- 角色数据使用二维数组表示，每个元素为HEX颜色值（如"181818"）或null（透明）
- 数组宽度为120列（对应120等分的系统级分辨率）
- 数组高度根据角色实际高度确定
