# 天干地支数据库分类方案整理

## 一、核心理念与目标

### 1.1 创业初衷
- **道商之学**：东城希望通过商业实战验证国学的商业价值，想把中国数术学发扬光大
- **宇宙密码**：天干地支乃博大精深的规律系统
- **思维方式**：取向比类的思维方式，提升AI智慧，助力AGI发展

### 2.2 核心要解决的问题
- **AI幻觉问题**：通过规律算法，让AI知道哪些数据可以发散，哪些不能发散
- **思考可解释性**：让AI的思考过程可追溯，区分"自己的想法"和"深思熟虑的结果"
- **智能决策**：根据场景快速做出精准决策，找到正确的思考方法

### 1.3 分类的本质目标
- **规律算法**：万变不离其宗的架构
- **智能体思考架构**：作为智能体的技术架构，主要用于训练AI、AI思考机制
- **决策支持**：根据阴阳五行判断是发散还是沿用，是否需要创意，是否考虑风险

## 二、系统设计要点

### 2.1 分类颗粒度
- **按行记录分类**：每条数据记录对应天干/地支分类
- **前期重点**：主要对知识库进行分类

### 2.2 阴阳区分（重要发现）
- **阳数据**：集体数据，相对稳定，成熟具象，目标长远，具备的无需计划的
  - 代表：甲、丙、戊、庚、壬
  - 特点：不需要过多改动，相对一致
- **阴数据**：个体数据，个性化差异化，可以多样性，计划中但不具备的
  - 代表：乙、丁、己、辛、癸
  - 特点：每个智能体可以有自己的想法
- **举例**：甲乙通常指skills从阴到阳代表从乙到甲，我们有量化的等级根据使用次数判断甲乙，1.0版本最高30级

### 2.3 地支藏干的处理
- **场景记忆**：记住场景，根据场景调用对应数据
- **比例偏差**：承认比例会有偏差，但场景本身能指导数据调用
- **待解决问题**：是否需要权重或标签组合系统？

### 2.4 多属性数据处理
- **分别记录**：同时包含多种属性的数据，分别记录

### 2.5 分类一致性维护
- **AI审核**：通过函数、AI和skills来维护分类一致性
- **分类改变记录表**：记录分类变更历史

### 2.6 边界处理
- **不适合分类的数据**：不需要用于AI思考的、没有规律的（如ID、姓名等）
- **未分类类别**：需要设置"未分类"或"待分类"类别
- **模糊处理**：不好分的场景可以相对模糊，或标记为"待分类"并说明原因

## 三、关键质疑与深入问题

### 3.1 关于"80%正确率"的质疑
**问题**：你说"基本80%确定的"，这个80%是如何得出的？是基于什么样本或测试？

**深入思考**：
- 如果80%正确，那20%错误会如何影响AI决策？
- 是否需要建立"置信度"机制？
- 如何量化分类的准确性？

### 3.2 关于"按行记录分类"的质疑
**问题**：一条记录可能包含多个概念，比如"技术文档"可能同时包含：
- 甲木（专业技术）
- 壬水（信息收集）
- 庚金（管理制度）

**质疑**：
- 如果一条记录只能有一个天干/地支，是否会丢失信息？
- 如果一条记录可以有多个标签，如何避免标签爆炸？
- 是否需要主标签+辅助标签的设计？

### 3.3 关于"阴数据个性化"的挑战
**问题**：你说"阴的数据每个智能体可能都不一样"，这带来几个问题：

**质疑**：
- 如果同一个数据在不同智能体中有不同分类，如何保证知识库的一致性？
- 智能体A认为某数据是"乙木（创意）"，智能体B认为是"丁火（营销）"，哪个是对的？
- 是否需要"个人知识库"和"集体知识库"的分离？

### 3.4 关于"地支场景识别"的模糊性
**问题**：你说"根据场景就知道要调用哪些数据"，但：

**质疑**：
- 如何让AI自动识别当前对话属于哪个地支场景？
- 如果场景识别错误，会不会导致调用错误的数据？
- 是否需要场景分类的元数据系统？

### 3.5 关于"五行相生相克"的实际应用
**问题**：你说"可以根据这个去达到平衡，知道问题出在哪里"，但：

**质疑**：
- 如何量化"不平衡"？比如"木克土"表示技术研发耗钱，如何用数据体现？
- 相生相克关系是用于数据关联，还是用于业务规则判断？
- 是否需要建立"五行平衡度"的监控指标？

## 四、技术实现建议
 1. **场景识别层**：根据场景锁定对话意图识别地支
 2. **藏干解析层**：根据地支找到对应的天干组合
 3. **阴阳判断层**：判断是发散（阴）还是沿用（阳）
 4. **五行过滤层**：根据五行相生相克关系过滤数据

**查询流程**：
```
用户问题 → 场景识别（地支） → 藏干解析（天干组合） → 
阴阳判断（发散/沿用） → 五行过滤 → 返回数据
```
