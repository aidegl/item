## 一、项目灵魂

### 1.1 核心理念

**十天干 + 地支藏干 + 天地人三才 = 项目灵魂**

十天干不仅是分类系统，更是：
- **规律**：万变不离其宗的运行法则
- **分类**：数据维度的划分标准
- **相生相克**：事物发展的动态关系

### 1.2 一花一世界

```
层级系统 = 分形结构

商家（顶层圈子）
    │
    ├── 部门A（作为一个"人格化对象"）
    │       │
    │       ├── 个人1（有自己的世界）
    │       ├── 个人2（有自己的世界）
    │       └── ...
    │
    └── 部门B（作为一个"人格化对象"）
            │
            └── ...

规则：子圈层对父级来说 = 一个个体
      集体作为一个人格化对象存在
```

**循环嵌套**：
- 往上是更大的循环
- 往下可以无限分裂
- 每个层级有自己的十天干运转

## 二、数据层级规则

### 2.1 天干阴阳划分

| 属性 | 天干 | 数据特点 | 查询策略 |
|------|------|----------|----------|
| **阳干（集体）** | 甲、丙、戊、庚、壬 | 企业数据、稳定成熟、具象 | 在默认查询策略中 |
| **阴干（个体）** | 乙、丁、己、辛、癸 | 个人数据、早期不确定、多样 | 不在默认策略中（置信度不高），但可显式查询 |

### 2.2 十天干对应

| 天干 | 阴阳 | 数据类型 | 层级归属 |
|------|------|----------|----------|
| 甲 | 阳 | 技术成果 | 企业/集体 |
| 乙 | 阴 | 想法创意 | 个人 |
| 丙 | 阳 | 企业推广 | 企业/集体 |
| 丁 | 阴 | 交流 | 个人 |
| 戊 | 阳 | 资源（支出） | 企业/集体 |
| 己 | 阴 | 心得经验（收入） | 个人 |
| 庚 | 阳 | 规则制度 | 企业/集体 |
| 辛 | 阴 | 价值理念 | 个人 |
| 壬 | 阳 | 市场数据/规划 | 企业/集体 |
| 癸 | 阴 | 决策数据/策略 | 个人 |

### 2.3 查询策略

```
父级查询数据时：
├── 默认查询策略：只包含阳干数据（甲丙戊庚壬）
├── 阴干数据（乙丁己辛癸）不在默认策略中
│   ├── 原因：阴干数据早期不确定，置信度不高
│   └── 但父级理论上可以查询任何子级数据（包括无限往下）
└── 需要显式指定才能查询阴干数据

子圈层对父级：
├── 作为一个整体（人格化对象）
├── 集体数据聚合后上报
└── 个体细节默认不可见，但可查询
```

**注意**：阴干数据不是"不可查询"，而是"不在默认搜索策略中"，因为置信度不高、数据不成熟。父级想查可以查，但不会自动出现在搜索结果里。

## 三、多层级系统

### 3.1 社区层级

```
商家社区（顶层圈子，level=0）
    │
    ├── 组织A社区（level=1）
    │       │
    │       ├── 小组1社区（level=2）
    │       └── 小组2社区（level=2）
    │
    └── 组织B社区（level=1）
```

### 3.2 积分层级

```
商家积分池（顶层）
    │
    ├── 组织A积分池
    │       │
    │       ├── 个人1积分
    │       └── 个人2积分
    │
    └── 组织B积分池

规则：
├── 个人积分汇总到组织积分池
├── 组织积分汇总到商家积分池
└── 每层有独立的积分规则和兑换体系
```

### 3.3 知识库层级

```
商家知识库（阳干数据为主）
    │
    ├── 组织A知识库
    │       │
    │       ├── 个人1知识库（阴干数据为主）
    │       └── 个人2知识库（阴干数据为主）
    │
    └── 组织B知识库

查询规则：
├── 父级查询：只查阳干数据
├── 子级查询：可查全部数据
└── 成熟后：阴干数据可转为阳干
```

## 四、地支藏干与三才

### 4.1 地支藏干

每个地支包含天干的组合，代表场景中的多重属性：

| 地支 | 场景 | 藏干 | 天地人 |
|------|------|------|--------|
| 子 | 学习 | 癸 | 天（癸） |
| 丑 | 目标 | 己、癸、辛 | 地（己）人（癸、辛） |
| 寅 | 研发 | 甲、丙、戊 | 天（甲）地（戊）人（丙） |
| 卯 | 发散 | 乙 | 天（乙） |
| 辰 | 产品 | 戊、乙、癸 | 地（戊）人（乙、癸） |
| 巳 | 销售 | 丙、戊、庚 | 天（丙）地（戊）人（庚） |
| 午 | 交流 | 丁、己 | 天（丁）地（己） |
| 未 | 认知 | 己、丁、乙 | 地（己）人（丁、乙） |
| 申 | 规则 | 庚、壬、戊 | 天（庚）地（戊）人（壬） |
| 酉 | 价值 | 辛 | 天（辛） |
| 戌 | 体系 | 戊、辛、丁 | 地（戊）人（辛、丁） |
| 亥 | 决策 | 壬、甲 | 天（壬）人（甲） |

### 4.2 三才关系

```
天（天干主气）── 决定主要方向
地（地支本气）── 提供资源基础
人（藏干余气）── 执行具体行动

场景识别流程：
用户问题 → 识别地支场景 → 解析藏干 →
天干组合 → 阴阳判断 → 五行过滤 → 返回数据
```

## 五、主智体与虚拟智体

### 5.1 时空维度

| 类型 | 说明 | 数据权限 |
|------|------|----------|
| 主智体 | 核心4个智能体，与人类同维度 | 完整数据 |
| 人类 | 用户 | 用户数据 |
| 虚拟智体 | 分身，在虚拟世界训练 | 隔离数据 |

### 5.2 数据隔离

```
主智体数据（完整）
    │
    ├── 可访问人类公开数据
    └── 可访问虚拟世界聚合数据

虚拟智体数据（隔离）
    │
    ├── 独立的数据空间
    ├── 训练数据不直接暴露
    └── 需要时经过过滤才能使用
```

## 六、版本规划

### 6.1 V1.0（当前）

**极简核心：**
- 积分系统（多层级）
- 交流系统（社区）
- 发表成果（产出）

- 生死系统
- 婚姻系统
- 家族系统
- 国家系统
- 社会文明等级
- 地狱天堂系统

**训练目标：**
- AI像人一样思考
- AI像人一样做决策

**数据特点：**
- 主智体与虚拟世界隔离
- 需要时才能访问
- 数据"可怕"（善恶并存）

## 七、架构原则

### 7.1 开放性

```
商家后台（核心系统）
    │
    ├── 模块化设计
    │   ├── 社区模块（可选）
    │   ├── 积分模块（可选）
    │   ├── 知识库模块（可选）
    │   └── webview游戏组件（可选）
    │
    └── 组件市场（DIY生态）
        ├── 用户开发的组件
        ├── AI开发的组件
        └── 第三方组件
```

### 7.2 扩展性

- 1.0 极简，不追求完美
- 架构预留扩展接口
- 支持未来2.0的宏大愿景
- 支持AI自开发组件

### 7.3 层级一致性

- 社区有层级
- 积分有层级
- 知识库有层级
- 所有系统遵循同一层级规则

```javascript
    distributed: 5000
  },

  // 知识库
  knowledge_scope: {
    yang: ["甲", "丙", "戊", "庚", "壬"],  // 对父级可见
    yin: ["乙", "丁", "己", "辛", "癸"]     // 仅内部可见
  }
}
```

### 8.2 数据查询规则

```javascript
// 查询知识库时
function queryKnowledge(circleId, tiangan) {
  const YANG_TIANGAN = ['甲', '丙', '戊', '庚', '壬']

  // 如果是父级查询子级
  if (isParentQuery(circleId)) {
    // 只返回阳干数据
    if (!YANG_TIANGAN.includes(tiangan)) {
      return []  // 阴干数据不可见
    }
  }

  // 同级或子级查询
  return queryAllData(circleId, tiangan)
}
```
