## 📝 明道云对话记录技能修复（2026-03-01 下午）

### 问题背景
- 用户要求保留 OpenClaw → 明道云的消息记录功能
- 删除明道云 → OpenClaw 的轮询/推送功能（因为系统消息循环注入、无影云无法开放端口）
- 原有 auto-hook.js 使用字段别名（如 `neirong`），但明道云 API 需要实际字段 ID

### 修复内容

#### 1. 修复 auto-hook.js 字段 ID
```javascript
// 修复前：使用别名
{ id: 'neirong', value: content }

// 修复后：使用实际字段 ID
{ id: '68da906bd34347b006235da5', value: content }
```

**字段 ID 映射：**
| 字段 | 对话工作表 ID | 消息工作表 ID |

| 发起人 | `68da90c3432b11f7ba68cb6c` | - |
| 接收人 | `692bfbb1e22247ab9a654f3d` | - |
| 对话 | - | `68da9105d34347b006235df6` |

| 日期 | `692cf82fe22247ab9a67d78d` | `692d166992609b5d9de82b58` |

#### 2. 创建 auto-record-daemon.js
**功能：** 监控 OpenClaw 会话文件，自动记录用户消息和 AI 回复

```javascript
// 核心逻辑
- 监控 /home/admin/.openclaw/agents/main/sessions/*.jsonl
- 检测 message.role === 'user' → 记录用户消息
- 检测 message.role === 'assistant' → 记录 AI 回复
- 避免重复记录（使用 recordedMessages Set）
```

#### 3. 修复缓存问题
```javascript
// 问题：dialogCache 初始化为 null，导致 Cannot read properties of null
// 修复：确保缓存总是对象
function ensureCache() {
  if (!dialogCache || typeof dialogCache !== 'object') {
    dialogCache = {};
  }
}
```

#### 4. 清理无用文件

- 其他缓存和日志文件

**保留：**

#### 5. 更新文档

### 经验教训
1. **明道云 API 字段 ID**：必须使用实际字段 ID，不是别名（neirong 等）
2. **缓存初始化**：确保对象类型，避免 null 引用
3. **消息去重**：使用 Set 记录已处理的消息 ID
4. **日志清理**：定期清理 daemon.log 避免过大
